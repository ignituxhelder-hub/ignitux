# IGINI exécute les tâches et la conformité — Plan d'implémentation

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** IGINI rédige le travail (ou donne les étapes exactes) pour les tâches et les exigences de conformité choisies, en série, puis l'humain valide ou refuse.

**Architecture:** Un module backend `igini/execution` (un appel IA structuré par élément, via `ClaudeService.generateStructuredOutput`, qui applique déjà droits d'offre et plafond de coût). Résultats stockés en colonnes nullables sur `tasks` et dans une nouvelle table `project_compliance_ai_runs`. Le frontend boucle sur les éléments cochés, une requête à la fois, et s'arrête à la première erreur de limite.

**Tech Stack:** NestJS + Prisma 7 + zod + vitest (backend), Next.js 15 + vitest + Testing Library (frontend). Commentaires et libellés en français.

**Spec:** `docs/superpowers/specs/2026-10-03-taches-ia-design.md`

## Global Constraints

- Migration **additive uniquement** (jamais `--accept-data-loss`) ; lignes existantes inchangées (`NULL`). Helder applique en prod via `backend/scripts/migrer-prod.mjs`.
- Propriétaire du projet seul peut lancer/valider/refuser (`assertOwnsProject`) ; collaborateurs en lecture seule.
- Jamais de validation automatique : seul `validate` fait passer la tâche à `done` / coche la conformité.
- Un élément `a_valider` ou `valide` n'est pas relancé (idempotent, pas de double facturation).
- Un échec IA ne consomme pas de quota (le journal n'enregistre que les appels réussis, comportement existant de `ClaudeService`).
- Ne jamais prétendre avoir déposé une démarche : bouton « J'ai fait / J'ai déposé » côté conformité.
- Le prompt interdit d'inventer une référence légale absente de la source fournie.
- Rien n'est poussé sur `main` sans l'accord de Helder. Avant toute poussée : suite backend + frontend, lint, `npm run build` (frontend).
- Pas de `git stash` nu ; commits fréquents sur `feat/taches-ia`.

## Review Focus

- Quota épuisé au milieu d'un lot : le lot s'arrête, restants intacts, message « limite atteinte » (Tasks 8, 9).
- Double clic / relance d'un élément déjà `a_valider` : aucun nouvel appel IA (Tasks 3, 4).
- Élément d'un autre projet / non-propriétaire : 404/403, aucun appel IA (Tasks 3, 4).
- Sortie IA invalide ou erreur réseau : état `echec` retentable, pas de plantage du lot (Tasks 3, 8).
- Refuser puis relancer : le motif de refus est transmis au prompt (Task 3).
